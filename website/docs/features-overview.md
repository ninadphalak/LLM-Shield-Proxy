# LLM-Shield-Proxy Feature Catalog

Each feature has a stability tier based on its current test and deployment evidence:

* `Supported` - CI exercises the feature end to end against its target infrastructure. Each entry
  states what CI verified and what remains untested.
* `Beta` - tests cover the code, but substitute an external system or depend heavily on operator
  configuration. Run an integration test before production use.
* `Experimental` - the target infrastructure has not been exercised end to end here, or the
  feature implements only part of a protocol. Validate it before any production traffic.
* `Research` - an exploration with known limits and no support commitment. **It may be removed in
  any release without a migration path. Do not make it a production dependency.**

Tiers describe verification status, not code quality. See
[Stability Tiers](https://github.com/ninadphalak/LLM-Shield-Proxy/blob/main/STABILITY.md) for the
full definitions and the deprecation policy.
## Section A: Data Protection & PII Redaction
* `Supported` **[Supported PII & Sensitive Data Types](/docs/features/data-protection-pii-redaction/supported-pii-types.md)**: All ten native Tier 1 detector patterns are exercised with redaction, non-disclosure, and rehydration assertions; Tier 2 entropy and the Tier 3 `PERSON` fallback have separate tests. Model-defined semantic types remain dependent on the operator-supplied model and corpus.
* `Supported` **[Tier 1 Pre-Compiled Regex Engine](/docs/features/data-protection-pii-redaction/tier-1-pre-compiled-regex-engine.md)**: Uses pre-compiled built-in patterns. Operator-defined BYOR patterns use `google-re2` to reject unsupported constructs and avoid backtracking behavior.
* `Supported` **[Tier 2 Shannon Entropy Scanner](/docs/features/data-protection-pii-redaction/tier-2-shannon-entropy-scanner.md)**: Applies configured length and Shannon-entropy thresholds to supported token candidates. False positives and false negatives depend on corpus and thresholds.
* `Supported` **[Tier 3 Quantized ONNX BERT-NER](/docs/features/data-protection-pii-redaction/tier-3-quantized-onnx-bert-ner.md)**: Runs a compatible operator-supplied ONNX entity model. Accuracy, latency, and memory depend on the model, corpus, and host. CI runs a checksum-pinned quantized DistilBERT model through real `onnxruntime` inference. The current engine supplies only `input_ids` and `attention_mask`; a model that also requires `token_type_ids` falls back to regex. It also labels every non-`O` prediction as `PERSON` instead of reading `id2label`.
* `Beta` **[Stateless Mutation Engine (AST-Aware Semantic PII Firewall)](/docs/features/data-protection-pii-redaction/stateless-ast-aware-semantic-pii-firewall.md)**: The catch-all route sends top-level JSON-RPC `2.0` objects through the AES-GCM stateless mutation path using `SHIELD_ENCRYPTION_KEY`. Supported leaf and schema transformations are documented; downstream compatibility must be tested.
* `Supported` **[Dynamic Schema Rewriting](/docs/features/data-protection-pii-redaction/dynamic-schema-rewriting.md)**: Can add cryptographic context fields to OpenAI/MCP tool schemas. Schema changes do not compel provider behavior; echo and rehydration must be integration-tested for the selected model and parser.
* `Supported` **[Format-Preserving Synthetic Masking & Entropy](/docs/features/data-protection-pii-redaction/format-preserving-synthetic-masking-entropy.md)**: Replaces detected values with deterministic, format-aware substitutes intended to retain useful syntax. Downstream task quality is workload-dependent.
* `Beta` **[In-Band Stateless Cryptographic Masking](/docs/features/data-protection-pii-redaction/in-band-stateless-cryptographic-masking.md)**: Places AES-256-GCM ciphertext in supported payload values using the operator's `SHIELD_ENCRYPTION_KEY`. It avoids a token mapping database but does not control other logs or storage systems.
* `Supported` **[Redis TTL Vault](/docs/features/data-protection-pii-redaction/stateless-redis-ttl-vault.md)**: Stores session mappings as plaintext JSON in Redis with a configured TTL. CI verifies cross-instance rehydration, rolling TTLs, tenant-key isolation, corrupt-payload handling, and session clearing against Redis 7. Cluster, Sentinel, TLS, ACLs, backups, and other Redis versions remain untested. Expiry does not prove that every copy is gone.
* `Beta` **[Granular Entity Policy Scopes](/docs/features/data-protection-pii-redaction/granular-entity-policy-scopes.md)**: Maps configured virtual-key identities to supported in-memory role and detector profiles. Unknown-identity and dependency behavior must be exercised for the selected resolver.
* `Beta` **[4-Mode Per-Request Masking Pipeline](/docs/features/data-protection-pii-redaction/4-mode-per-request-masking-pipeline.md)**: Supports dynamic masking mode selection per-request via the `X-Shield-Masking-Mode` header. Modes: `SYNTHETIC` (canonical locale swapping), `STRUCTURAL_TAG` (placeholder tokens), `SCRUB` (hard redaction), `STATELESS_CRYPTO` (AES-256-GCM envelope). The cryptographic mode requires `SHIELD_ENCRYPTION_KEY`.
* `Beta` **[Bring-Your-Own-Regex (BYOR) Custom Rules](/docs/features/data-protection-pii-redaction/bring-your-own-regex-byor-custom-rules.md)**: Loads operator-defined regex patterns from a YAML file via `CUSTOM_REGEX_PATH`, extending Tier 1 detection without code changes.
* `Supported` **[JSON Bomb / Payload Nesting Depth Protection](/docs/features/data-protection-pii-redaction/json-bomb-payload-nesting-depth-protection.md)**: Rejects supported JSON payloads that exceed configured depth/bracket bounds. This reduces specific resource-exhaustion risks but is not a complete parser or denial-of-service defense.
## Section B: Streaming and Traffic Engineering
* `Supported` **[SSE Sliding-Window Buffer](/docs/features/ultra-low-latency-streaming-traffic-engineering/sub-millisecond-sse-sliding-window-buffer.md)**: Reconstructs tested placeholders split across SSE chunks with bounded trailing overlap. Published timings are component measurements, not end-to-end latency guarantees.
* `Research` **[Tool Catalog Policy Filter](/docs/features/ultra-low-latency-streaming-traffic-engineering/context-aware-mcp-discovery-pruner.md)**: Removes policy-denied tools from supported `tools/list` results and can cache the filtered list. It does not rank tools or infer task relevance. CI verifies its Redis path against Redis 7. It remains Research because it is part of a limited MCP route that the project does not commit to track.
* `Supported` **[Bounded Streaming JSON Lexer](/docs/features/ultra-low-latency-streaming-traffic-engineering/zero-allocation-streaming-json-lexer.md)**: Parses incremental JSON/SSE data without retaining the complete response history; allocations and RSS are benchmarked explicitly.
* `Experimental` **[Multi-Provider Translators](/docs/features/ultra-low-latency-streaming-traffic-engineering/multi-provider-translators.md)**: Translates a documented subset of OpenAI-style requests and Anthropic events. Unsupported fields and provider semantics require integration tests.
* `Experimental` **[Anthropic Adapter Implementation](/docs/features/ultra-low-latency-streaming-traffic-engineering/anthropic-adapter-implementation.md)**: Translates a text-focused subset of OpenAI-style requests and Anthropic events. It is unit-tested but not validated against the provider protocol.
* `Research` **[Pluggable Tool-Call RBAC (MCP Governance)](/docs/features/ultra-low-latency-streaming-traffic-engineering/pluggable-tool-call-rbac-mcp-governance.md)**: Applies the configured resolver's allow/block decision to the `/v1/mcp` method subset. Empty allowlists deny all tools by default; intentional blocklist-only deployments require `MCP_EMPTY_ALLOWLIST_MODE=BLOCKLIST_ONLY` and emit a critical startup warning. See the [MCP Tool Governance guide](/docs/guides/mcp-tool-governance.md).
* `Experimental` **[OPA & Vault Stale-While-Revalidate RBAC Resolvers](/docs/features/ultra-low-latency-streaming-traffic-engineering/opa-vault-rbac-resolvers.md)**: Provides asynchronous OPA and Vault resolver implementations with local cached snapshots. Failure, staleness, refresh, concurrency, and backend policy behavior require deployment tests.
* `Supported` **[HTTP/2 Upstream Connection Pooling](/docs/features/ultra-low-latency-streaming-traffic-engineering/http-2-upstream-connection-pooling.md)**: Uses a shared `httpx` client with HTTP/2 enabled and configurable pool limits. In CI, eight concurrent requests multiplex over one TLS connection to a Hypercorn server, and an HTTP/1.1-only upstream still works. No commercial provider endpoint was tested.
* `Beta` **[Provider Failover with Per-Request Override](/docs/features/ultra-low-latency-streaming-traffic-engineering/provider-failover-with-per-request-override.md)**: Supports configured fallback routing through `X-Shield-Fallback-URL` or `FALLBACK_BASE_URL`, subject to override and egress policy. `FALLBACK_API_KEY` is used on the implemented failover path.
* `Beta` **[FinOps `stream_options` Injection](/docs/features/ultra-low-latency-streaming-traffic-engineering/automatic-finops-stream-options-injection.md)**: Adds `stream_options: {include_usage: true}` to supported streaming requests when FinOps metering is enabled. Attribution completeness depends on provider responses, identity, parser, and metric-delivery behavior.
## Section C: Traffic Controls and Resilience
* `Beta` **[Edge-Level Agent Identity Enforcer](/docs/features/agent_identity_enforcer.md)**: Validates configured JWT and DPoP conditions on supported governed paths and maintains a bounded replay cache. Trust still depends on issuer keys, audience policy, proxy placement, clock, and bypass controls.
* `Beta` **[Prompt Correlation Markers](/docs/features/advanced-threat-defense-enterprise-resilience/cryptographic-canary-prompt-tripwires.md)**: Injects an HMAC-derived marker when explicitly configured and stops the supported streamed response path if that marker is observed. It is a heuristic signal, not general prompt-extraction prevention.
* `Beta` **[Entity-Weighted Request Limits](/docs/features/advanced-threat-defense-enterprise-resilience/entity-weighted-blast-radius-limits.md)**: Applies a Redis or local token bucket to PII counts detected on the supported inbound catch-all path. It does not bound detector misses or the current response path.
* `Beta` **[Token Usage Cost Estimates](/docs/features/advanced-threat-defense-enterprise-resilience/llm-finops-chargeback-meter.md)**: Records supported provider-reported token usage with virtual-key labels. Billing-grade completeness requires identity, provider, parser, cardinality, and metric-retention validation.
* `Beta` **[Provider Failover Routing](/docs/features/advanced-threat-defense-enterprise-resilience/provider-failover-routing.md)**: Supports explicit header-driven routing to approved secondary provider mirrors. Availability and semantic equivalence depend on the configured upstreams.
* `Beta` **[Exponential Retries](/docs/features/advanced-threat-defense-enterprise-resilience/antifragile-exponential-retries.md)**: Retries the documented transient-status/error set with bounded attempts and asynchronous backoff. Tests use mocked responses; useful operation requires a configured upstream and can duplicate non-idempotent effects.
* `Beta` **[Agent Loop Circuit Breaker](/docs/features/advanced-threat-defense-enterprise-resilience/composite-agent-loop-circuit-breaker.md)**: Returns HTTP 429 after the configured number of consecutive duplicate request signals for one session. It is a bounded heuristic and can miss changing loops or flag legitimate repetition.
* `Beta` **[Traffic Controls and Resilience](/docs/features/advanced-threat-defense-enterprise-resilience/traffic-engineering-resiliency.md)**: Includes optional request limiting, bounded drain handling, retry/failover, and provider-key selection. Each control has topology- and failure-specific limits.
* `Supported` **[Graceful Shutdown / Pod Drain](/docs/features/advanced-threat-defense-enterprise-resilience/graceful-shutdown-pod-drain.md)**: Marks the process unready and waits up to `DRAIN_TIMEOUT_SECONDS` before closing managed resources. In CI, the built container receives `SIGTERM` and lets an 8-second request finish. The drain counter is process-local, does not coordinate across multiple workers, and has not been tested in a Kubernetes pod lifecycle.
* `Supported` **[Request-ID Correlation & Sanitization](/docs/features/advanced-threat-defense-enterprise-resilience/request-id-correlation-sanitization.md)**: Validates a client `X-Request-ID` or generates a UUID4. CI verifies normal, streaming, probe, 401, and sanitized-500 responses, including replacement of CRLF input. The drain 429 has no request ID because it is built before assignment.
* `Experimental` **[Multi-Provider Upstream Key Registry](/docs/features/advanced-threat-defense-enterprise-resilience/multi-provider-upstream-key-registry.md)**: Selects configured keys for four exact hostnames and otherwise falls back to `UPSTREAM_API_KEY`. It does not currently implement Azure hostname/header handling.
## Section D: Audit and Evidence
* `Supported` **[Tamper-Evident Audit Logging with Hash Chaining](/docs/features/enterprise-auditing-compliance/worm-compliant-audit-logging-with-hash-chaining.md)**: SHA-256 chains and Ed25519-signs privacy-safe audit metadata. The default mode is non-blocking and best-effort; opt-in durable modes append, flush, and acknowledge local JSONL evidence. Regulatory WORM claims require a separately configured immutable retention system.
* `Beta` **[Stream Digest Receipt](/docs/features/enterprise-auditing-compliance/stream-digest-receipt.md)**: Generates a rolling SHA-256 digest over the client-facing SSE stream and emits a signed receipt. This attests to observed stream bytes; the configured-upstream conformance test is the evidence for the narrower raw-PII boundary claim.
* `Experimental` **[Decision Trace Exporter](/docs/features/enterprise-auditing-compliance/universal-decision-trace-exporter.md)**: A library class can emit caller-supplied decision metadata through OSCAL, OpenTelemetry, and optional transports. Runtime proxy routes do not currently invoke it automatically.
* `Beta` **[Asynchronous OpenTelemetry (OTel) Tracing](/docs/features/enterprise-auditing-compliance/zero-overhead-opentelemetry-otel-tracing.md)**: Propagates supported W3C `traceparent` context and sends completed spans through a bounded batch processor. CI verifies export to an in-memory collector and checks serialized spans for fixture PII. OTLP-over-HTTP and a real collector remain untested.
* `Experimental` **[GRC Webhook & Sidecar File Transport](/docs/features/enterprise-auditing-compliance/grc-webhook-sidecar-file-transport.md)**: Provides webhook and JSONL file transport primitives for caller-wired OSCAL events. The running proxy has no current environment-based wiring or vendor-specific connector.
* `Research` **[Zero-Width Correlation Marker](/docs/features/enterprise-auditing-compliance/dynamic-canary-watermarking-steganography.md)**: Adds a keyed zero-width marker to supported output. A decoder can recover the marker if it survives, but the marker is removable and does not prove who disclosed content.
* `Supported` **[Cryptographic KAT & RFC 6902 Differential Audit Logging](/docs/features/enterprise-auditing-compliance/fips-140-3-kat-rfc-6902-differential-audit-logging.md)**: Performs implementation self-tests and emits differential metadata. It does not make the Python distribution or host cryptographic module FIPS validated.
* `Supported` **[NIST OSCAL Assessment Results Generation](/docs/features/enterprise-auditing-compliance/nist-oscal-assessment-results-generation.md)**: Produces OSCAL 1.2 `assessment-results` artifacts on demand. The format supports NIST SP 800-53 control assessment; it is not a compliance determination.
* `Supported` **[Security Response Headers](/docs/features/enterprise-auditing-compliance/security-response-headers-on-all-responses.md)**: Sets `X-Content-Type-Options`, `X-Frame-Options`, and HSTS on supported application responses. CI verifies success, 401, streaming, probe, and sanitized-500 responses. The drain 429 does not include them.
* `Beta` **[Applied Role Name in Audit Events](/docs/features/enterprise-auditing-compliance/applied-role-name-in-audit-events.md)**: Instrumented request events can include `applied_role_name`. Presence, identity binding, and coverage must be verified for the event types used as evidence.
* `Supported` **[Ed25519-Signed Audit Receipts](/docs/features/enterprise-auditing-compliance/ed25519-signed-audit-receipts.md)**: Configured audit records can be hash chained and Ed25519-signed; the public key is exposed at `GET /api/v1/audit/pubkey`. Trust depends on stable key custody, complete collection, and verification.
* `Supported` **[Compliance-Pack CLI Export](/docs/features/enterprise-auditing-compliance/compliance-pack-cli-export.md)**: `llm-shield-proxy compliance-report --framework=[hipaa|soc2|nist]` verifies a supplied tamper-evident chain and Ed25519 signatures, summarizes OSCAL results, and bundles a SHA-256 integrity manifest plus a generated Markdown summary.
## Section E: Infrastructure and Service Mesh
* `Experimental` **[Service Mesh gRPC ext_proc Integration](/docs/features/secure-infrastructure-service-mesh/service-mesh-native-grpc-ext-proc-integration.md)**: Supports Envoy `ext_proc` buffer exchange over a Unix Domain Socket. Compatibility and overhead depend on the Envoy filter configuration, timeouts, and deployment topology.
* `Experimental` **[Vault Secrets and mTLS](/docs/features/secure-infrastructure-service-mesh/centralized-enterprise-secrets-mtls.md)**: Retrieves supported secrets from HashiCorp Vault and configures selected X.509 client and trust credentials. Key custody, renewal, outage behavior, and the complete connection path require deployment testing.
* `Experimental` **[Kubernetes Mutating Webhook](/docs/features/secure-infrastructure-service-mesh/zero-dependency-kubernetes-mutating-webhook.md)**: Includes a Python admission-webhook path for injecting the sidecar configuration. Admission security, availability, mutation scope, and resource usage require cluster-specific validation. *(`helm template --set webhook.enabled=true` renders in CI, and the render is checked for one shared CA across the serving certificate and the admission `caBundle` and for the `/v1/k8s/mutate` path matching the app route. No cluster admission install has been performed.)*
* `Supported` **[Component Health Probes and Prometheus Alert Rules](/docs/features/secure-infrastructure-service-mesh/deep-component-health-probes-and-prometheus-alert-rules.md)**: `/readyz` checks selected PII-engine, Vault-cache, and Redis state; `/livez` is shallow. CI tests Redis 7, the running container routes, Helm rendering, and rule syntax with `promtool`. No pod has been scheduled from either chart, and no Prometheus server has evaluated the rules.
* `Beta` **[Role-Based Policy-as-Code & Hot-Reloading](/docs/features/secure-infrastructure-service-mesh/role-based-policy-as-code-hot-reloading.md)**: Polls a YAML policy file and stores supported identity-to-role mappings in memory. Validate reload timing, unknown identities, and request-scoped override behavior under concurrency.
* `Beta` **[Request-Scoped Dynamic Overrides](/docs/features/secure-infrastructure-service-mesh/universal-dynamic-override-engine.md)**: Uses `ContextVar` for supported per-tenant overrides and `copy_context().run()` where documented. Exercising request-level behavior requires an operator-supplied policy file and identity mapping.
* `Research` **[Dynamic Tool Schema Rewriting](/docs/features/secure-infrastructure-service-mesh/dynamic-mcp-tool-schema-rewriting.md)**: Recursively augments supported tool schemas with `_ctx_hash_<prop>` sibling fields for string properties. Schema rewriting cannot compel an LLM or parser to return those fields, so echo and rehydration require integration tests.
* `Experimental` **[UDS Socket Permission Hardening](/docs/features/secure-infrastructure-service-mesh/uds-socket-toctou-hardening.md)**: On Linux, the `ext_proc` Unix socket is created under `umask(0o117)`. This removes a create-then-`chmod` permission window; it is not a complete local privilege-escalation defense.
* `Experimental` **[Reproducible Benchmarks & Signed Supply Chain](/docs/features/secure-infrastructure-service-mesh/ci-cd-supply-chain-security.md)**: CI workflows describe benchmark publication, keyless Sigstore/cosign signing, and SPDX SBOM attestation. The local benchmark is covered separately by the conformance feature; supply-chain execution has no package module or covering test under `tests/`.
* `Supported` **[Streaming Privacy Conformance Harness](/docs/features/secure-infrastructure-service-mesh/reproducible-streaming-privacy-conformance.md)**: Produces a JSON report that checks split replacement tokens, valid SSE, restored values, and whether known test values appear in the outgoing provider request. It also reports local allocation and timing measurements, not end-to-end service latency.
* `Supported` **[SSRF & DNS-Rebinding Egress Firewall](/docs/features/secure-infrastructure-service-mesh/ssrf-dns-rebinding-egress-firewall.md)**: Checks HTTP(S) URLs in supported MCP `tools/call` arguments. It resolves all returned A and AAAA records and rejects the call if policy denies the domain or any resolved IP, including private, loopback, and cloud-metadata ranges.
