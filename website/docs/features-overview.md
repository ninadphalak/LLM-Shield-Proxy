# LLM-Shield-Proxy Feature Catalog

Each feature carries a stability tier describing how much independent evidence exists that it
works outside the maintainer's machine:

* `Supported` - runs from `pip install llm-shield-proxy` with no external infrastructure, and is
  reproducible by a third party in minutes.
* `Beta` - covered by tests, but requires external infrastructure or substantial operator
  configuration. Integration-test before production.
* `Experimental` - targets infrastructure not yet exercised end-to-end in this repository, or
  implements a deliberate protocol subset. Not for a production traffic path without your own
  validation.

Tiers describe verification status, not code quality. See
[Stability Tiers](https://github.com/ninadphalak/LLM-Shield-Proxy/blob/main/STABILITY.md) for the
full definitions and the deprecation policy.
## Section A: Data Protection & PII Redaction
* `Supported` **[Supported PII & Sensitive Data Types](/docs/features/data-protection-pii-redaction/supported-pii-types.md)**
* `Supported` **[Tier 1 Pre-Compiled Regex Engine](/docs/features/data-protection-pii-redaction/tier-1-pre-compiled-regex-engine.md)**: Uses `google-re2` for supported pre-compiled patterns, avoiding catastrophic backtracking while rejecting unsupported constructs.
* `Supported` **[Tier 2 Shannon Entropy Scanner](/docs/features/data-protection-pii-redaction/tier-2-shannon-entropy-scanner.md)**: Applies configured length and Shannon-entropy thresholds to supported token candidates. False positives and false negatives depend on corpus and thresholds.
* `Beta` **[Tier 3 Quantized ONNX BERT-NER](/docs/features/data-protection-pii-redaction/tier-3-quantized-onnx-bert-ner.md)**: Runs an operator-selected ONNX entity model for contextual extraction. Accuracy, latency, and memory depend on the selected model, corpus, and host. *(Requires `ONNX_MODEL_PATH`; falls back to heuristic keyword detection when not set.)*
* `Supported` **[Stateless Mutation Engine (AST-Aware Semantic PII Firewall)](/docs/features/data-protection-pii-redaction/stateless-ast-aware-semantic-pii-firewall.md)**: The catch-all route sends top-level JSON-RPC `2.0` objects through the AES-GCM stateless mutation path using `SHIELD_ENCRYPTION_KEY`. Supported leaf and schema transformations are documented; downstream compatibility must be tested.
* `Supported` **[Dynamic Schema Rewriting](/docs/features/data-protection-pii-redaction/dynamic-schema-rewriting.md)**: Can add cryptographic context fields to OpenAI/MCP tool schemas. Schema changes do not compel provider behavior; echo and rehydration must be integration-tested for the selected model and parser.
* `Supported` **[Format-Preserving Synthetic Masking & Entropy](/docs/features/data-protection-pii-redaction/format-preserving-synthetic-masking-entropy.md)**: Replaces detected values with deterministic, format-aware substitutes intended to retain useful syntax. Downstream task quality is workload-dependent.
* `Supported` **[In-Band Stateless Cryptographic Masking](/docs/features/data-protection-pii-redaction/in-band-stateless-cryptographic-masking.md)**: Places AES-256-GCM ciphertext in supported payload values using the operator's `SHIELD_ENCRYPTION_KEY`. It avoids a token mapping database but does not control other logs or storage systems.
* `Beta` **[Redis TTL Vault](/docs/features/data-protection-pii-redaction/stateless-redis-ttl-vault.md)**: Stores session mappings with a configured TTL in Redis. Expiry is a retention control, not a guarantee that replicas, backups, or downstream systems hold no data.
* `Beta` **[Granular Entity Policy Scopes](/docs/features/data-protection-pii-redaction/granular-entity-policy-scopes.md)**: Maps configured virtual-key identities to supported in-memory role and detector profiles. Unknown-identity and dependency behavior must be exercised for the selected resolver.
* `Supported` **[4-Mode Per-Request Masking Pipeline](/docs/features/data-protection-pii-redaction/4-mode-per-request-masking-pipeline.md)**: Supports dynamic masking mode selection per-request via the `X-Shield-Masking-Mode` header. Modes: `SYNTHETIC` (canonical locale swapping), `STRUCTURAL_TAG` (placeholder tokens), `SCRUB` (hard redaction), `STATELESS_CRYPTO` (AES-256-GCM envelope).
* `Supported` **[Bring-Your-Own-Regex (BYOR) Custom Rules](/docs/features/data-protection-pii-redaction/bring-your-own-regex-byor-custom-rules.md)**: Allows loading operator-defined regex patterns from a `custom_regex.yaml` file via `CUSTOM_REGEX_PATH`, extending Tier 1 detection without code changes.
* `Supported` **[JSON Bomb / Payload Nesting Depth Protection](/docs/features/data-protection-pii-redaction/json-bomb-payload-nesting-depth-protection.md)**: Rejects supported JSON payloads that exceed configured depth/bracket bounds. This reduces specific resource-exhaustion risks but is not a complete parser or denial-of-service defense.
## Section B: Ultra-Low Latency Streaming & Traffic Engineering
* `Supported` **[SSE Sliding-Window Buffer](/docs/features/ultra-low-latency-streaming-traffic-engineering/sub-millisecond-sse-sliding-window-buffer.md)**: Reconstructs tested placeholders split across SSE chunks with bounded trailing overlap. Published timings are component measurements, not end-to-end latency guarantees.
* `Beta` **[Context-Aware Tool Catalog Pruner](/docs/features/ultra-low-latency-streaming-traffic-engineering/context-aware-mcp-discovery-pruner.md)**: Filters supported `tools/list` result shapes through the resolved policy and offers bounded caching. A smaller catalog may reduce prompt size; it cannot guarantee agent behavior.
* `Supported` **[Bounded Streaming JSON Lexer](/docs/features/ultra-low-latency-streaming-traffic-engineering/zero-allocation-streaming-json-lexer.md)**: Parses incremental JSON/SSE data without retaining the complete response history; allocations and RSS are benchmarked explicitly.
* `Supported` **[Multi-Provider Translators](/docs/features/ultra-low-latency-streaming-traffic-engineering/multi-provider-translators.md)**: Translates a documented subset of OpenAI-style requests and Anthropic events. Unsupported fields and provider semantics require integration tests.
* `Supported` **[Anthropic Adapter Implementation](/docs/features/ultra-low-latency-streaming-traffic-engineering/anthropic-adapter-implementation.md)**: Translates a documented subset of OpenAI-style requests and Anthropic streaming events. Exercise model names, roles, tools, multimodal blocks, errors, and unsupported fields before deployment.
* `Experimental` **[Pluggable Tool-Call RBAC (MCP Governance)](/docs/features/ultra-low-latency-streaming-traffic-engineering/pluggable-tool-call-rbac-mcp-governance.md)**: Applies the configured resolver's allow/block decision to the `/v1/mcp` method subset. The default in-memory resolver is permissive unless policy is supplied; see the [MCP Tool Governance guide](/docs/guides/mcp-tool-governance.md).
* `Experimental` **[OPA & Vault Stale-While-Revalidate RBAC Resolvers](/docs/features/ultra-low-latency-streaming-traffic-engineering/opa-vault-rbac-resolvers.md)**: Provides asynchronous OPA and Vault resolver implementations with local cached snapshots. Failure, staleness, refresh, concurrency, and backend policy behavior require deployment tests.
* `Beta` **[HTTP/2 Upstream Connection Pooling](/docs/features/ultra-low-latency-streaming-traffic-engineering/http-2-upstream-connection-pooling.md)**: Maintains persistent keepalive connection pools with configurable limits (`HTTP_MAX_CONNECTIONS`, `HTTP_MAX_KEEPALIVE_CONNECTIONS`) using HTTP/2 multiplexing to upstream providers.
* `Beta` **[Provider Failover with Per-Request Override](/docs/features/ultra-low-latency-streaming-traffic-engineering/provider-failover-with-per-request-override.md)**: Supports configured fallback routing through `X-Shield-Fallback-URL` or `FALLBACK_BASE_URL`, subject to override and egress policy. `FALLBACK_API_KEY` is used on the implemented failover path.
* `Beta` **[FinOps `stream_options` Injection](/docs/features/ultra-low-latency-streaming-traffic-engineering/automatic-finops-stream-options-injection.md)**: Adds `stream_options: {include_usage: true}` to supported streaming requests when FinOps metering is enabled. Attribution completeness depends on provider responses, identity, parser, and metric-delivery behavior.
## Section C: Advanced Threat Defense & Enterprise Resilience
* `Beta` **[Edge-Level Agent Identity Enforcer](/docs/features/agent_identity_enforcer.md)**: Validates configured JWT and DPoP conditions on supported governed paths and maintains a bounded replay cache. Trust still depends on issuer keys, audience policy, proxy placement, clock, and bypass controls.
* `Beta` **[Canary Prompt Tripwires](/docs/features/advanced-threat-defense-enterprise-resilience/cryptographic-canary-prompt-tripwires.md)**: Injects an HMAC-derived marker when explicitly configured and stops the supported streamed response path if that marker is observed. It is a heuristic tripwire, not general prompt-extraction prevention.
* `Beta` **[Entity-Weighted Blast Radius Limits](/docs/features/advanced-threat-defense-enterprise-resilience/entity-weighted-blast-radius-limits.md)**: Applies a Redis or local token bucket to PII counts detected on the supported inbound catch-all path. It does not bound detector misses or the current response path.
* `Beta` **[LLM FinOps Meter](/docs/features/advanced-threat-defense-enterprise-resilience/llm-finops-chargeback-meter.md)**: Records supported provider-reported token usage with virtual-key labels. Billing-grade completeness requires identity, provider, parser, cardinality, and metric-retention validation.
* `Beta` **[Provider Failover Routing](/docs/features/advanced-threat-defense-enterprise-resilience/provider-failover-routing.md)**: Supports explicit header-driven routing to approved secondary provider mirrors. Availability and semantic equivalence depend on the configured upstreams.
* `Supported` **[Exponential Retries](/docs/features/advanced-threat-defense-enterprise-resilience/antifragile-exponential-retries.md)**: Retries the documented transient-status/error set with bounded attempts and asynchronous backoff. Retries can increase latency and duplicate non-idempotent effects.
* `Beta` **[Composite Agent Loop Circuit Breaker](/docs/features/advanced-threat-defense-enterprise-resilience/composite-agent-loop-circuit-breaker.md)**: Returns HTTP 429 after the configured number of consecutive duplicate request signals for one session. It is a bounded heuristic and can miss changing loops or flag legitimate repetition.
* `Beta` **[Traffic Engineering & Resiliency](/docs/features/advanced-threat-defense-enterprise-resilience/traffic-engineering-resiliency.md)**: Includes optional request limiting, bounded drain handling, retry/failover, and provider-key selection. Each control has topology- and failure-specific limits.
* `Supported` **[Graceful Shutdown / Pod Drain](/docs/features/advanced-threat-defense-enterprise-resilience/graceful-shutdown-pod-drain.md)**: The application lifecycle marks readiness as draining and waits up to `DRAIN_TIMEOUT_SECONDS` before closing managed resources. Platform termination deadlines and unmanaged tasks can still interrupt work.
* `Supported` **[Request-ID Correlation & Sanitization](/docs/features/advanced-threat-defense-enterprise-resilience/request-id-correlation-sanitization.md)**: Validates a client `X-Request-ID` against an allowlist or generates a UUID4. Verify propagation on success, streaming, application errors, and infrastructure-generated responses.
* `Experimental` **[Multi-Provider Upstream Key Registry](/docs/features/advanced-threat-defense-enterprise-resilience/multi-provider-upstream-key-registry.md)**: Selects configured keys for four exact hostnames and otherwise falls back to `UPSTREAM_API_KEY`. It does not currently implement Azure hostname/header handling.
## Section D: Enterprise Auditing & Compliance
* `Supported` **[Tamper-Evident Audit Logging with Hash Chaining](/docs/features/enterprise-auditing-compliance/worm-compliant-audit-logging-with-hash-chaining.md)**: SHA-256 chains and Ed25519-signs privacy-safe audit metadata. The default mode is non-blocking and best-effort; opt-in durable modes append, flush, and acknowledge local JSONL evidence. Regulatory WORM claims require a separately configured immutable retention system.
* `Beta` **[Stream Digest Receipt](/docs/features/enterprise-auditing-compliance/stream-digest-receipt.md)**: Generates a rolling SHA-256 digest over the client-facing SSE stream and emits a signed receipt. This attests to observed stream bytes; the configured-upstream conformance test is the evidence for the narrower raw-PII boundary claim.
* `Experimental` **[Decision Trace Exporter](/docs/features/enterprise-auditing-compliance/universal-decision-trace-exporter.md)**: A library class can emit caller-supplied decision metadata through OSCAL, OpenTelemetry, and optional transports. Runtime proxy routes do not currently invoke it automatically.
* `Beta` **[Asynchronous OpenTelemetry (OTel) Tracing](/docs/features/enterprise-auditing-compliance/zero-overhead-opentelemetry-otel-tracing.md)**: Handles W3C `traceparent` propagation through a bounded background path. Queueing reduces request-path work but does not imply zero overhead or lossless delivery.
* `Experimental` **[GRC Webhook & Sidecar File Transport](/docs/features/enterprise-auditing-compliance/grc-webhook-sidecar-file-transport.md)**: Provides webhook and JSONL file transport primitives for caller-wired OSCAL events. The running proxy has no current environment-based wiring or vendor-specific connector.
* `Beta` **[Dynamic Canary Watermarking & Steganography](/docs/features/enterprise-auditing-compliance/dynamic-canary-watermarking-steganography.md)**: Tracks provenance for internal leak forensics by injecting invisible, verifiable cryptographic watermarks (zero-width Unicode) into outbound text streams, keyed to a per-session HMAC fingerprint.
* `Supported` **[Cryptographic KAT & RFC 6902 Differential Audit Logging](/docs/features/enterprise-auditing-compliance/fips-140-3-kat-rfc-6902-differential-audit-logging.md)**: Performs implementation self-tests and emits differential metadata. It does not make the Python distribution or host cryptographic module FIPS validated.
* `Supported` **[NIST OSCAL Assessment Results Generation](/docs/features/enterprise-auditing-compliance/nist-oscal-assessment-results-generation.md)**: Produces OSCAL 1.2 `assessment-results` artifacts on demand. The format supports NIST SP 800-53 control assessment; it is not a compliance determination.
* `Supported` **[Security Response Headers](/docs/features/enterprise-auditing-compliance/security-response-headers-on-all-responses.md)**: Application middleware sets `X-Content-Type-Options`, `X-Frame-Options`, and HSTS on responses traversing that path; verify ingress- and server-generated responses separately.
* `Beta` **[Applied Role Name in Audit Events](/docs/features/enterprise-auditing-compliance/applied-role-name-in-audit-events.md)**: Instrumented request events can include `applied_role_name`. Presence, identity binding, and coverage must be verified for the event types used as evidence.
* `Supported` **[Ed25519-Signed Audit Receipts](/docs/features/enterprise-auditing-compliance/ed25519-signed-audit-receipts.md)**: Configured audit records can be hash chained and Ed25519-signed; the public key is exposed at `GET /api/v1/audit/pubkey`. Trust depends on stable key custody, complete collection, and verification.
* `Supported` **[Compliance-Pack CLI Export](/docs/features/enterprise-auditing-compliance/compliance-pack-cli-export.md)**: `llm-shield-proxy compliance-report --framework=[hipaa|soc2|nist]` verifies a supplied tamper-evident chain and Ed25519 signatures, summarizes OSCAL results, and bundles a SHA-256 integrity manifest plus a generated Markdown summary.
## Section E: Secure Infrastructure & Service Mesh
* `Experimental` **[Service Mesh gRPC ext_proc Integration](/docs/features/secure-infrastructure-service-mesh/service-mesh-native-grpc-ext-proc-integration.md)**: Supports Envoy `ext_proc` buffer exchange over a Unix Domain Socket. Compatibility and overhead depend on the Envoy filter configuration, timeouts, and deployment topology.
* `Experimental` **[Centralized Enterprise Secrets & mTLS](/docs/features/secure-infrastructure-service-mesh/centralized-enterprise-secrets-mtls.md)**: Secures backend communications via native HashiCorp Vault integrations (AppRole / K8s / Token) combined with a non-blocking TTL cache and X.509 mTLS transport.
* `Experimental` **[Kubernetes Mutating Webhook](/docs/features/secure-infrastructure-service-mesh/zero-dependency-kubernetes-mutating-webhook.md)**: Includes a Python admission-webhook path for injecting the sidecar configuration. Admission security, availability, mutation scope, and resource usage require cluster-specific validation.
* `Beta` **[Component Health Probes and Prometheus Alert Rules](/docs/features/secure-infrastructure-service-mesh/deep-component-health-probes-and-prometheus-alert-rules.md)**: `/readyz` checks selected PII-engine, Vault-cache, and Redis state; `/livez` is shallow. The Helm chart includes alert rules, while delivery depends on operator monitoring configuration.
* `Beta` **[Role-Based Policy-as-Code & Hot-Reloading](/docs/features/secure-infrastructure-service-mesh/role-based-policy-as-code-hot-reloading.md)**: Polls a YAML policy file and stores supported identity-to-role mappings in memory. Validate reload timing, unknown identities, and request-scoped override behavior under concurrency.
* `Supported` **[Request-Scoped Dynamic Overrides](/docs/features/secure-infrastructure-service-mesh/universal-dynamic-override-engine.md)**: Uses `ContextVar` for supported per-tenant overrides and `copy_context().run()` where documented. Only allowlisted, request-safe settings should be exposed.
* `Experimental` **[Dynamic Tool Schema Rewriting](/docs/features/secure-infrastructure-service-mesh/dynamic-mcp-tool-schema-rewriting.md)**: Recursively augments supported tool schemas with `_ctx_hash_<prop>` sibling fields for string properties. Schema rewriting cannot compel an LLM or parser to return those fields, so echo and rehydration require integration tests.
* `Experimental` **[UDS Socket TOCTOU Hardening](/docs/features/secure-infrastructure-service-mesh/uds-socket-toctou-hardening.md)**: On Linux, the ext_proc Unix Domain Socket is created with a strict `umask(0o117)` before socket creation (rather than `chmod` after) to prevent local privilege-escalation races.
* `Supported` **[Reproducible Benchmarks & Signed Supply Chain](/docs/features/secure-infrastructure-service-mesh/ci-cd-supply-chain-security.md)**: CI re-runs the latency/memory benchmark suite on every push and publishes results to the Job Summary; releases are keylessly signed with Sigstore/cosign (GitHub OIDC) and shipped with an attached SPDX SBOM attestation.
* `Supported` **[Streaming Privacy Conformance Harness](/docs/features/secure-infrastructure-service-mesh/reproducible-streaming-privacy-conformance.md)**: Produces a machine-readable, environment-stamped report covering fragmented placeholders, SSE reconstruction, the pre-upstream privacy boundary, allocation observations, and p50/p95/p99 in-process timings.
* `Supported` **[SSRF & DNS-Rebinding Egress Firewall](/docs/features/secure-infrastructure-service-mesh/ssrf-dns-rebinding-egress-firewall.md)**: Intercepts every MCP `tools/call` argument for `http(s)://` URLs, resolves every A/AAAA record (not just the first), and rejects fail-closed against a per-virtual-key CIDR/domain-wildcard policy if any resolved IP lands in RFC 1918, loopback, or cloud-metadata space.
