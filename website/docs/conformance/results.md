# Published Conformance Results

## Published LLM-Shield-Proxy Run

The repository includes a machine-readable v1.0.0 report at `benchmarks/results/conformance-v1.0.0-1.6.0-windows.json`. It covers all six scored domains and includes the required timing distributions. The timing and allocation values apply only to the recorded environment and operations; they are not end-to-end latency or process-wide memory limits.

**Run:** 2026-09-04 on Windows 11, CPython 3.14.7, AMD64; 10,000 timing samples per operation. LLM-Shield-Proxy 1.6.0.

**Source revision:** `007994bf4e164cdd40f1b2eb0c8ac5d96df95d35` -- a plain commit hash, so the run is reproducible from that commit.

**SHA-256:** `c468ebb8a808613573eba66b5192359217ba2812dbf2216f71085baa18db5054`

This result was generated by the project's maintainer on a single machine. No external contributor has replicated it yet.

An earlier pre-release report, `conformance-v1.0.0-pre-release-windows.json`, was **deprecated and deleted on 2026-09-06**. Its source label ended in `+working-tree`, meaning the run included uncommitted source changes and therefore could not be reproduced from any commit; an artefact nobody can re-execute is not evidence, whatever it reports. The figures on this page now come from the clean-tree run above. On every push to `main`, the `Reproducible Public Benchmark` workflow creates a new report tied to the latest commit.

| Domain | Latest Status |
| :--- | :--- |
| Fragmentation safety | Pass - 11 partitions, no reported failures |
| Raw protected-data egress | Pass - email, SSN, and credit-card fixtures absent at tested boundary |

*Latency is reported but not scored. The previous `latency_measurement` check was removed because it only verified non-negative durations.*

These figures measure isolated in-process Python operations on a single Windows machine, excluding factors like ASGI, HTTP, TLS, network time, model response time, concurrency, and durable audit I/O. The reported 32-byte peak covers only the declared Python allocation scope, not the entire process RSS. This report supersedes earlier reports generated prior to recent streaming-path optimizations.
