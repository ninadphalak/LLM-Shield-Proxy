# LLM-Shield-Proxy Feature Catalog
## Section A: Data Protection & PII Redaction
* **[Supported PII & Sensitive Data Types](docs/features/data-protection-pii-redaction/supported-pii-types.md)**
* **[Tier 1 Pre-Compiled Regex Engine](docs/features/data-protection-pii-redaction/tier-1-pre-compiled-regex-engine.md)**: Leverages `google-re2` for high-performance, pre-compiled regular expressions that guarantee O(N) execution time and complete immunity against ReDoS attacks.
* **[Tier 2 Shannon Entropy Scanner](docs/features/data-protection-pii-redaction/tier-2-shannon-entropy-scanner.md)**: Automatically detects and flags unstructured cryptographic secrets and high-entropy API keys by evaluating the Shannon entropy of incoming token streams.
* **[Tier 3 Quantized ONNX BERT-NER](docs/features/data-protection-pii-redaction/tier-3-quantized-onnx-bert-ner.md)**: Employs a strictly quantized ONNX BERT-NER model executing natively in-memory to provide high-accuracy contextual free-text extraction (e.g., Medical Diagnoses, Bank Accounts, Organization Names) with sub-millisecond latency. *(Requires `ONNX_MODEL_PATH` to be configured; falls back to heuristic keyword detection when not set.)*
* **[Stateless Mutation Engine (AST-Aware Semantic PII Firewall)](docs/features/data-protection-pii-redaction/stateless-ast-aware-semantic-pii-firewall.md)**: Inspects and safely mutates structured tool invocations. Auto-detects `jsonrpc: 2.0` to forcefully bypass standard text masking and apply `STATELESS_SYNTHETIC`.
* **[Dynamic Schema Rewriting (The "Force Echo" Mechanism)](docs/features/data-protection-pii-redaction/dynamic-schema-rewriting.md)**: Dynamically rewrites the OpenAI/MCP tool schema on the fly to inject cryptographic context as `required` fields, mathematically forcing the LLM to echo them back for zero-Redis multi-instance rehydration.
* **[Format-Preserving Synthetic Masking & Entropy](docs/features/data-protection-pii-redaction/format-preserving-synthetic-masking-entropy.md)**: Replaces sensitive tokens with mathematically and structurally coherent canonical locale substitutes to preserve downstream LLM attention weights and syntax.
* **[In-Band Stateless Syntheticgraphic Masking](docs/features/data-protection-pii-redaction/in-band-stateless-cryptographic-masking.md)**: Secures data in transit using zero-data AES-256-GCM envelope encryption directly within the payload.
* **[Stateless Redis TTL Vault](docs/features/data-protection-pii-redaction/stateless-redis-ttl-vault.md)**: Employs ephemeral Redis TTL vaults to support session-isolated tokenization with zero-data liability and automatic expiry.
* **[Granular Entity Policy Scopes](docs/features/data-protection-pii-redaction/granular-entity-policy-scopes.md)**: Provides robust department-level security profiles utilizing O(1) in-memory tenant profile mapping via Virtual Keys enforcing a FAIL_CLOSED Zero-Trust default.
* **[4-Mode Per-Request Masking Pipeline](docs/features/data-protection-pii-redaction/4-mode-per-request-masking-pipeline.md)**: Supports dynamic masking mode selection per-request via the `X-Shield-Masking-Mode` header. Modes: `SYNTHETIC` (canonical locale swapping), `STRUCTURAL_TAG` (placeholder tokens), `SCRUB` (hard redaction), `STATELESS_SYNTHETIC` (AES-256-GCM envelope).
* **[Bring-Your-Own-Regex (BYOR) Custom Rules](docs/features/data-protection-pii-redaction/bring-your-own-regex-byor-custom-rules.md)**: Allows loading operator-defined regex patterns from a `custom_regex.yaml` file via `CUSTOM_REGEX_PATH`, extending Tier 1 detection without code changes.
* **[JSON Bomb / Payload Nesting Depth Protection](docs/features/data-protection-pii-redaction/json-bomb-payload-nesting-depth-protection.md)**: Enforces a strict recursive depth limit on inbound JSON payloads to prevent stack overflow attacks and CPU exhaustion.
## Section B: Ultra-Low Latency Streaming & Traffic Engineering
* **[Sub-Millisecond SSE Sliding-Window Buffer](docs/features/ultra-low-latency-streaming-traffic-engineering/sub-millisecond-sse-sliding-window-buffer.md)**: Processes fragmented stream chunks securely in real-time by reconstructing overlapping tokens without breaking Server-Sent Events (SSE) streaming connections.
* **[Context-Aware Tool Catalog Pruner](docs/features/ultra-low-latency-streaming-traffic-engineering/context-aware-mcp-discovery-pruner.md)**: Intercepts and sanitizes MCP tools/list catalogs via non-blocking ASGI middleware, utilizing BLAKE3-hashed multi-tenant caching and dynamic TTL clamping to prevent prompt bloat and agent hallucinations.
* **[Zero-Allocation Streaming JSON Lexer](docs/features/ultra-low-latency-streaming-traffic-engineering/zero-allocation-streaming-json-lexer.md)**: Utilizes a highly optimized, Rust-backed `orjson` parser to evaluate continuous data streams while maintaining a lean memory footprint.
* **[Multi-Provider Translators](docs/features/ultra-low-latency-streaming-traffic-engineering/multi-provider-translators.md)**: Democratizes multi-cloud routing through zero-SDK OpenAI-to-Anthropic request transformation and dynamic SSE stream normalization.
* **[Anthropic Adapter Implementation](docs/features/ultra-low-latency-streaming-traffic-engineering/anthropic-adapter-implementation.md)**: Provides seamless schema translations for Anthropic models directly at the network edge without requiring client-side SDK modifications. Handles system-prompt extraction, multi-content-block responses, and enforces strictly alternating message roles per the Anthropic API contract.
* **[Pluggable Tool-Call RBAC (MCP Governance)](docs/features/ultra-low-latency-streaming-traffic-engineering/pluggable-tool-call-rbac-mcp-governance.md)**: Intercepts autonomous JSON-RPC tool executions and enforces strict logical access controls against your existing Redis infrastructure.
* **[OPA & Vault Stale-While-Revalidate RBAC Resolvers](docs/features/ultra-low-latency-streaming-traffic-engineering/opa-vault-rbac-resolvers.md)**: High-performance, fail-closed asynchronous resolvers for Open Policy Agent and HashiCorp Vault ensuring O(1) fast-path execution via atomic dictionary swaps and robust thundering herd prevention.
* **[HTTP/2 Upstream Connection Pooling](docs/features/ultra-low-latency-streaming-traffic-engineering/http-2-upstream-connection-pooling.md)**: Maintains persistent keepalive connection pools with configurable limits (`HTTP_MAX_CONNECTIONS`, `HTTP_MAX_KEEPALIVE_CONNECTIONS`) using HTTP/2 multiplexing to upstream providers.
* **[Provider Failover with Per-Request Override](docs/features/ultra-low-latency-streaming-traffic-engineering/provider-failover-with-per-request-override.md)**: Allows clients to specify a fallback upstream URL via the `X-Shield-Fallback-URL` header or configure a global `FALLBACK_BASE_URL`. Automatic key-swapping to `FALLBACK_API_KEY` on failover.
* **[Automatic FinOps `stream_options` Injection](docs/features/ultra-low-latency-streaming-traffic-engineering/automatic-finops-stream-options-injection.md)**: Automatically injects `stream_options: {include_usage: true}` into streaming requests when FinOps metering is enabled, ensuring accurate token attribution without requiring client changes.
## Section C: Advanced Threat Defense & Enterprise Resilience
* **[Edge-Level Agent Identity Enforcer](docs/features/agent_identity_enforcer.md)**: Cryptographic Zero-Trust ingress barrier that intercepts autonomous agent tool-calls, strictly validating mathematically signed Workload Identity and DPoP proofs in <1ms.
* **[Cryptographic Canary Prompt Tripwires](docs/features/advanced-threat-defense-enterprise-resilience/cryptographic-canary-prompt-tripwires.md)**: Defends against aggressive extraction attempts by planting verifiable inbound honeytokens and enforcing immediate outbound Generator Exit socket drops upon triggered violations.
* **[Entity-Weighted Blast Radius Limits](docs/features/advanced-threat-defense-enterprise-resilience/entity-weighted-blast-radius-limits.md)**: Prevents dangerous bulk data exfiltration events by implementing horizontally scalable Redis Token-Bucket circuit breakers keyed by PII entity count rather than request count.
* **[LLM FinOps Chargeback Meter](docs/features/advanced-threat-defense-enterprise-resilience/llm-finops-chargeback-meter.md)**: Facilitates strict multi-tenant chargebacks and resource accounting by streaming asynchronous Prometheus metrics that track token consumption down to the individual identity.
* **[Provider Failover Routing](docs/features/advanced-threat-defense-enterprise-resilience/provider-failover-routing.md)**: Guarantees zero-downtime service continuity via explicit header-driven rerouting to secondary provider mirrors without subjecting clients to unapproved model downgrades.
* **[Antifragile Exponential Retries](docs/features/advanced-threat-defense-enterprise-resilience/antifragile-exponential-retries.md)**: Swiftly recovers from upstream instability by implementing native asyncio jitter and exponential backoffs to elegantly absorb severe network timeouts and 429/50x errors.
* **[Composite Agent Loop Circuit Breaker](docs/features/advanced-threat-defense-enterprise-resilience/composite-agent-loop-circuit-breaker.md)**: Automatically halts runaway AutoGen and CrewAI autonomous loops by dynamically tracking array depths and recursive tool call patterns.
* **[Traffic Engineering & Resiliency](docs/features/advanced-threat-defense-enterprise-resilience/traffic-engineering-resiliency.md)**: Hardens infrastructure via Redis evalsha Token-Bucket Rate Limiters (6000 RPM/200 Burst), Kubernetes 25s SIGTERM connection draining, and robust upstream key overriding.
* **[Graceful Shutdown / Pod Drain](docs/features/advanced-threat-defense-enterprise-resilience/graceful-shutdown-pod-drain.md)**: On `SIGTERM`, the proxy sets a draining flag, waits up to `DRAIN_TIMEOUT_SECONDS` (default 25s) for in-flight requests to complete, then cleanly shuts down the connection pool, gRPC server, and Vault refresh loop.
* **[Request-ID Correlation & Sanitization](docs/features/advanced-threat-defense-enterprise-resilience/request-id-correlation-sanitization.md)**: Forwards client-supplied `X-Request-ID` headers downstream after validating against a strict safe-character regex, or generates a UUID4 if absent. Echoed back on all responses.
* **[Multi-Provider Upstream Key Registry](docs/features/advanced-threat-defense-enterprise-resilience/multi-provider-upstream-key-registry.md)**: Auto-resolves the correct upstream API key (OpenAI, Gemini, Anthropic, DeepSeek) based on the target hostname, supporting centralized key management without per-request client configuration.
## Section D: Enterprise Auditing & Compliance
* **[WORM-Compliant Audit Logging with Hash Chaining](docs/features/enterprise-auditing-compliance/worm-compliant-audit-logging-with-hash-chaining.md)**: Emits structured compliance events containing timestamps, tenant IDs, redacted entity types, and session metadata. Every log entry is cryptographically chained to its predecessor using SHA-256, providing mathematical tamper-evidence for SOC 2 and HIPAA audits.
* **[Cryptographic Proof of Non-Egress Stream Attestation](docs/features/enterprise-auditing-compliance/cryptographic-proof-of-non-egress-stream-attestation.md)**: Generates a rolling SHA-256 digest over the outgoing SSE stream and emits an HMAC-signed attestation receipt at stream end, providing per-session proof of zero PII egress.
* **[Universal Decision Trace Exporter](docs/features/enterprise-auditing-compliance/universal-decision-trace-exporter.md)**: Enriches enterprise observability platforms by emitting highly structured NIST OSCAL decision artifacts intertwined comprehensively with OpenTelemetry spans.
* **[Zero-Overhead OpenTelemetry (OTel) Tracing](docs/features/enterprise-auditing-compliance/zero-overhead-opentelemetry-otel-tracing.md)**: Ensures full observability without latency penalties by handling W3C traceparent distributed tracing propagation via a dedicated asynchronous background thread with bounded queue size.
* **[GRC Webhook & Sidecar File Transport](docs/features/enterprise-auditing-compliance/grc-webhook-sidecar-file-transport.md)**: Dispatches OSCAL decision payloads to external risk platforms (Vanta, Drata, Sprinto) via a pluggable transport layer supporting async HTTP webhooks and Kubernetes sidecar file appending.
* **[Dynamic Canary Watermarking & Steganography](docs/features/enterprise-auditing-compliance/dynamic-canary-watermarking-steganography.md)**: Tracks provenance for internal leak forensics by injecting invisible, verifiable cryptographic watermarks (zero-width Unicode) into outbound text streams, keyed to a per-session HMAC fingerprint.
* **[FIPS 140-3 KAT & RFC 6902 Differential Audit Logging](docs/features/enterprise-auditing-compliance/fips-140-3-kat-rfc-6902-differential-audit-logging.md)**: Satisfies stringent federal requirements through strict compliance logging formats, cryptographic self-tests (SHA-256 + AES-256-GCM), and RFC 6902 differential patching.
* **[NIST OSCAL Assessment Results Generation](docs/features/enterprise-auditing-compliance/nist-oscal-assessment-results-generation.md)**: Produces NIST SP 800-53 Rev. 5 compliant `assessment-results` JSON artifacts on-demand via the `DecisionTraceExporter`, linking every RBAC decision to a Segmented Hash Chain for auditor review.
* **[Security Response Headers on All Responses](docs/features/enterprise-auditing-compliance/security-response-headers-on-all-responses.md)**: Automatically injects `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, and `Strict-Transport-Security` (HSTS, 1-year) on all proxy responses.
* **[Applied Role Name in Audit Events](docs/features/enterprise-auditing-compliance/applied-role-name-in-audit-events.md)**: All audit log events include the `applied_role_name` field, enabling precise attribution of which YAML policy role governed each request.
## Section E: Secure Infrastructure & Service Mesh
* **[Service Mesh Native gRPC ext_proc Integration](docs/features/secure-infrastructure-service-mesh/service-mesh-native-grpc-ext-proc-integration.md)**: Eliminates redundant HTTP network hops by streaming buffers directly over Unix Domain Sockets for immediate Envoy sidecar compatibility.
* **[Centralized Enterprise Secrets & mTLS](docs/features/secure-infrastructure-service-mesh/centralized-enterprise-secrets-mtls.md)**: Secures backend communications via native HashiCorp Vault integrations (AppRole / K8s / Token) combined with a non-blocking TTL cache and X.509 mTLS transport.
* **[Zero-Dependency Kubernetes Mutating Webhook](docs/features/secure-infrastructure-service-mesh/zero-dependency-kubernetes-mutating-webhook.md)**: Enables frictionless drop-in K8s integration via an embedded Python admission webhook controller operating entirely within the FastAPI event loop with zero persistent memory footprint.
* **[Deep Component Health Probes and Prometheus Alert Rules](docs/features/secure-infrastructure-service-mesh/deep-component-health-probes-and-prometheus-alert-rules.md)**: Provides granular native endpoints for K8s liveness and readiness probes covering Redis connectivity and Vault mTLS states, alongside pre-packaged alert rules.
* **[Role-Based Policy-as-Code & Hot-Reloading](docs/features/secure-infrastructure-service-mesh/role-based-policy-as-code-hot-reloading.md)**: Automates zero-downtime file polling for live policy updates with an O(1) in-memory flattening architecture that maps incoming `virtual_key_id` requests to distinct security roles.
* **[Universal Dynamic Override Engine](docs/features/secure-infrastructure-service-mesh/universal-dynamic-override-engine.md)**: Enables O(1) hash lookups via `contextvars.ContextVar`, thread-safe off-loop Executor propagation using `copy_context().run()`, and the ability to override any global `.env` configuration per-tenant without function-signature bloat.
* **[Dynamic MCP Tool Schema Rewriting](docs/features/secure-infrastructure-service-mesh/dynamic-mcp-tool-schema-rewriting.md)**: Automatically augments MCP and OpenAI function schemas to require `_ctx_hash_<prop>` sibling fields for all string properties, enabling stateless AES-256-GCM rehydration of redacted values via the Stateless Mutation Engine JSON-RPC path without any LLM-side changes.
* **[UDS Socket TOCTOU Hardening](docs/features/secure-infrastructure-service-mesh/uds-socket-toctou-hardening.md)**: On Linux, the ext_proc Unix Domain Socket is created with a strict `umask(0o117)` before socket creation (rather than `chmod` after) to prevent local privilege-escalation races.
